架空ブランドによる自主制作。実在ジムの模写・商標再現は行っていない。

- **制作日**: 2026-08-02
- **目的**: 無料カウンセリングの予約獲得
- **ターゲット**: 20〜40代女性（メインは渋谷勤務の30代前半）

## 制作上の判断

- **テキストは画像に焼き込まず、すべてHTML/CSSで実装した。** 日本語をAI画像生成すると文字が崩れやすく、修正コストも高いため。AI生成画像は写真ビジュアルの役割に限定している。
- **アクセントカラーは三角配色を採用しなかった。** ベースのスモーキーローズから+150°で算出すると深緑（`#4f9e6e`）になり、AI生成物に頻出する配色で安く見えるため、暖色域のブラスゴールド（`#C08A3E`）を明示指定した。
- **お客様の声に顔写真を使っていない。** 実在しない人物の顔写真を「利用者の声」として提示すると誤認を招くため、頭文字のイニシャルバッジ＋年代・職業で表現している。
- **数値表現に注記を必ず併記している。** 「−7kg」は平均値である旨と「効果には個人差があります」を同一視界内に配置。景品表示法上のリスクを避けるとともに、誠実さ自体を競合との差別化に転換する意図。
- **スマホ版のヒーローは、写真にコピーを重ねる構成をやめた。** スクリムを濃くするとモデルの顔が隠れ、薄くするとCTAと注記が読めなくなるため、SPのみ「コピー → 写真」の上下2段構成にしている（PCは左テキスト／右写真のまま）。
- **悩み共感セクションはPCで4列ではなく2×2にした。** 4列だと日本語見出しが「落ち／る。」のように1文字だけ折り返されるため。
- **動画にCTA画面を入れていない。** ループ再生前提のため、締めのCTAが数秒ごとに繰り返されると不自然になる。LP側のCTAボタンへ接続する設計。
- **画像はPNGからJPEG（品質78）へ変換した。** 配信重量が31MB→4.3MBになる。PNG原本は `references/original-png/` に保管。
- **ヒーロー背景動画は遅延読み込みにした。** ヒーローはLCP（表示速度の指標）に直結するため、まずポスター画像を表示し、`window.load` 後に動画を読み込んで再生可能になってからフェードインで差し替える。`prefers-reduced-motion`、データセーバー、3G以下の回線では動画を読み込まず静止画のままにする。
- **ヒーローのポスターは動画の先頭フレームを使っている。** 別の静止画を使うと、動画へ切り替わる瞬間に構図が跳ねるため。

## ヒーロー動画の制作手段について（要確認）

`hero-pc` / `hero-sp` の2本は、**Premiere Proではなく ffmpeg で制作している。** 制作中にPremiere MCPのブリッジが応答しなくなり（`/tmp/premiere-mcp-bridge/` のコマンドが消費されない状態）、`ad/clarive-hero-loops.prproj` を作成できなかったため。

現行版は **Remotionで組んだ4カット構成のスライド転換ループ**（10.27秒）。

実装: `projects/remotion-sandbox/src/ClariveHeroBg.tsx`
コンポジション: `ClariveHeroPc`（1920×1080）／`ClariveHeroSp`（1080×1040）
配信用への変換: `scripts/encode-hero-remotion.mjs`

```bash
cd projects/remotion-sandbox
npx remotion studio                      # プレビュー
npx remotion render ClariveHeroPc out/clarive-hero-pc.mp4 --codec=h264 --crf=22
npx remotion render ClariveHeroSp out/clarive-hero-sp.mp4 --codec=h264 --crf=22
cd ../../portfolio/clarive-womens-personal-gym-lp
node scripts/encode-hero-remotion.mjs    # 音声除去・圧縮・ポスター抽出
```

**クロスディゾルブをやめ、スライド転換にした。** 人物が写ったカット同士を重ねると体が二重に見えるゴーストが出る。スライドなら2枚が混ざらないため、この問題が構造的に起きない。

- 4カット × 90フレーム（3秒）、転換は18フレーム（0.6秒）の右からのスライド、イージングは `Easing.inOut(cubic)`
- 各カット内で寄り／引きを交互に入れて単調さを回避（scale 1.00↔1.055、横方向に0.5〜0.6%の流し）
- **ループの継ぎ目**: 末尾に先頭カットを「動きを止めた状態」で置く。尺を転換より2フレーム長くしているのは、同尺だと転換が94%までしか進まず継ぎ目が出るため（PSNR 31.5dB → **42.5dB** に改善）
- スマホ版は同一コンポジションの `variant: "sp"` で、カットごとに `objectPosition` を変えて人物側を切り出している

### 旧版: Premiere Proでの4カット編集

`ad/clarive-hero-cut.prproj` に残っている。構成は同じ4カットだが、転換が**クロスディゾルブ**だったため、人物同士が重なる瞬間にゴーストが出た。編集設計は `copy/07-ヒーロー映像の編集設計.md`。

| カット | 素材 | 尺 | モーション |
|---|---|---|---|
| 1 | 全身・カールのトップ | 3.0s | 押し込み 80→83.2% |
| 2 | バストアップの寄り | 3.0s | 引き 83.2→80% |
| 3 | 女性トレーナーがフォームを見ている | 3.0s | 押し込み 80→82.4% |
| 4 | 個室の引き・窓の光 | 3.0s | 引き 82.4→80% |

- カット間は**20フレームのクロスディゾルブ**。各カットを独立トラック（V1〜V5）に置き、入ってくる絵が常に上に来るようにして不透明度キーフレームで重ねている
- **ループ処理**: 末尾にカット1をもう一度重ね、最終フレーム（11.967s）までにディゾルブを完了させる。これで末尾フレームと先頭フレームが一致する（実測 継ぎ目 PC 0.96 / SP 1.24）
- **押し込みと引きを交互**にして単調さを避けている
- 素材は2400×1350にアップスケールし、**スケール80%＝画面ぴったり**にしてある。寄っても常に等倍以下なので拡大による劣化が出ない
- 全カットで**左55%は無地の壁のまま**（見出し・CTAの可読性を確保）

**Premiereプロジェクト**: `ad/clarive-hero-cut.prproj`（シーケンス `CLARIVE_HERO_CUT` / 1920×1080 / 30fps）
**マスター**: `ad/hero-cut-master.mp4`（Premiereから書き出した19MB・PCM音声つき）
**配信用への変換**: `scripts/encode-hero-cut.mjs`（音声除去・H.264/VP9圧縮・スマホ用の切り出し・ポスター抽出）

### 廃止した方式（記録）

**方式A: ケンバーンズ**（`scripts/build-hero-loops.mjs`）
静止画1枚をゆっくりズーム＋パンさせるだけ。動きの量が足りず「トレーニングしている感じ」が出なかった。

**方式B: コマ撮り＋オプティカルフロー補間**（`scripts/generate-hero-motion.mjs` / `build-hero-motion.mjs`）
ダンベルカール1レップを16コマの静止画として生成し、`minterpolate` で繋いだ。**破綻したため廃止。**
連続フレームを並べると、腕だけでなく胴体の太さ・脚の位置・背景のラック・観葉植物までフレームごとに揺れていた。AI生成の静止画は同じ参照・同じプロンプトでも毎回わずかに違う絵として描かれ、画素レベルでは一致しない。補間はその差も「動き」として引き伸ばすため、人体が変形して見える。**静止画生成で連続的な手足の動きを作る限り、この揺れは原理的に消せない。**

→ 連続動作の偽装をやめ、構図の違うカット同士をディゾルブで繋ぐ編集（現行方式）に切り替えた。カット間で絵が変わるのは「編集」として自然に受け取られるため、この問題が発生しない。

素材は `references/motion-frames/`（方式Bの16コマ）に保管。

`clarive-loop-8s`（紹介動画）はPremiere Proで制作済み（`ad/clarive-loop-8s.prproj`）。

## ビフォーアフターの見せ方

**既定はスライダー**（つまみが最初から見える）。「2枚を並べて見る」ボタンで並べ表示に切り替わる。

### 2つの見せ方を用意した理由

縦バーで重ねる方式は、**体の左半分がBefore・右半分がAfterになり、BeforeもAfterも全身を一度も見られない。** これが当初「見にくい」と言われた原因。景色や部屋のリフォームのように画面全体が変わる素材では有効だが、中央に立つ人物ひとりの比較には構造的に向かない。

一方でスライダーには「訪問者自身が動かして変化を確かめる」体験価値があり、つまみが見えないと操作できることに気づけない。**2026-08-04にユーザー判断でスライダーを既定に戻し、並べ表示は切り替えで提供する形にした。**

スライダー表示のままでも変化が読み取れるよう、次を重ねている。

- BEFORE / AFTER ラベルに**体重を併記**（58.4kg / 50.9kg）
- 下部中央に**変化量バッジ**（−7.5kg）。人物に重ならない位置に置く

調査した内容（[LP制作リファレンス](https://notebooklm.google.com/notebook/18800b75-2da3-48fd-934b-0b5dc940f0d8) / Web）から反映した点:

- **ひと目で変化が理解できること**が最優先。操作させないと分からない見せ方にしない
- **具体的な数値**を写真に添える → 各写真に `58.4kg` / `50.9kg`、境目に `−7.5kg` のバッジ
- **属性を詳しく**（年齢・職業・産後などの背景）→ カード下部に記載
- **スマホでの見やすさを優先**（利用者の約7割）→ スマホでも2列を維持して隣接比較できるようにする
- スライダーは「訪問者自身が動かして変化を確かめる」体験価値があるので、**選べる形で残す**

### レイアウト上の工夫

- 2枚の間隔は 3px。**隣接させるほど輪郭の差を比べやすい**
- 差分バッジ（−7.5kg）は上部に置く。中央に置くと一番見せたいウエストに重なる
- BEFORE / AFTER のラベルと体重は写真下部にグラデーションを敷いて重ね、写真の面積を削らない
- AFTER側のラベル帯だけスモーキーローズにして、どちらが結果か一目で分かるようにする

`lp/images/ba-{a,b}-{before,after}.jpg`（760×1040）を使用。

**当初、比較として成立していなかった。** 原因は2つ。

1. **人物が画面中央にいて、バーを端に寄せても壁しか映らなかった** → 体が画面いっぱいに入る矩形へ切り抜き直した
2. **BeforeとAfterが画素レベルで揃っていなかった** → 中央で切り替えるとブラの位置も腰の高さもずれ、「加工に失敗した写真」に見えていた

### 位置合わせ（`scripts/align-before-after.py`）

輝度で人物を検出してバウンディングボックスを求め、Afterを「頭頂〜足元の高さ」と「左右中心」がBeforeと一致するよう拡大縮小＋平行移動してから、2枚を同一矩形で切り抜く。

- 背景差分方式は、壁と床で背景色が変わる構図・植物やベンチが写る構図で破綻したため不採用。**輝度 < 100 で人物を分離し、横方向は背景の什器を拾わないよう中央60%に絞る**
- 縦横比は 760:1040

### Beforeの作り直し（`scripts/regenerate-before.mjs`）

初回のBeforeはAfterとの差が小さく、スライダーを動かしても変化が読み取れなかった。**Afterを参照画像に渡してBeforeを生成し直し**、「同一人物・同一ポーズ・同一背景・同一カメラで、体型だけが違う」状態を作った。

- 位置合わせの補正量が ペアA 1.0225倍→**1.0093倍**、ペアB 0.9953倍→**1.0008倍**（ほぼ無補正）に改善
- 体型差は「2ヶ月で−7kg相当」の現実的な範囲にとどめている。誇張は景品表示法上のリスクがあるうえ、かえって嘘っぽく見えるため

### 致命的な不具合: 透明なメニューがページ全面を覆っていた

スライダーのつまみが実ブラウザで動かなかった真因は、スライダー側ではなく **`.sp-nav`（スマホ用メニュー）** にあった。

```css
.sp-nav { position: fixed; inset: 0; z-index: 99; display: flex; opacity: 0; }
```

`display: flex` が `hidden` 属性の `display: none` を打ち消すため、**透明なメニューが常にページ全面に乗り、ヘッダー（z-index: 100）以外のクリック・ドラッグをすべて飲み込んでいた。** スライダーだけでなく、CTAボタン・FAQ・カルーセルも本来は操作できていなかった。

修正:

```css
.sp-nav[hidden] { display: none; }
.sp-nav:not(.is-open) { pointer-events: none; }
```

**この不具合は合成イベントでのテストでは発見できなかった。** `dispatchEvent(new PointerEvent(...))` は要素に直接投げるためヒットテストを通らず、オーバーレイの存在が無視されてしまう。以降、操作要素の検証は CDP の `Input.dispatchMouseEvent`（本物の入力）で行う。

- `scripts/qa-slider-drag.mjs` — スライダーを実マウスでドラッグして検証
- `scripts/qa-slider-diagnose.mjs` — その座標で実際にクリックを拾う要素を特定する診断
- `scripts/qa-interactions.mjs` — オーバーレイ／スライダー／FAQ／カルーセル／CTAを一括検証（5/5 PASS）

### つまみの操作性

34px→44pxに拡大、ホバーで拡大＋影。画面に入ったとき一度だけ左右に振って操作可能であることを伝える（`prefers-reduced-motion` では無効）。ドラッグ・矢印キー・Home/End に対応。
