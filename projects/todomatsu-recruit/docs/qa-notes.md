## バグ修正（2026-07-30 追記⑯：スクロール後にハンバーガーメニューが途中で切れる）

ページを下にスクロールしてからハンバーガーメニューを開くと、メニューパネルが画面全体を覆わず、ヘッダーの実高さ（約70px）で途中から背後のページ内容が透けて見える不具合をユーザーからスクリーンショットで報告された。

**原因**：`Header.module.css`の`.headerScrolled`（`window.scrollY > 40`で付与）に設定していた`backdrop-filter: blur(10px)`が、CSS仕様上`position: fixed`の子要素に対する新しいcontaining blockを生成してしまう。`.menuOverlay`（`position: fixed; inset: 0`）は`<header>`の子要素だったため、スクロール時は本来の「ビューポート全体」ではなく「ヘッダー自身の高さ（70px）」を基準にfixed配置されてしまい、パネルがそこで切れていた。

**対応**：`Header.tsx`でメニュー（`AnimatePresence`ブロック）を`react-dom`の`createPortal`で`document.body`直下に描画するよう変更し、ヘッダーの`backdrop-filter`から完全に切り離した。あわせて`.menuOverlay`の`z-index`を`90`→`110`に引き上げ、`<header>`自体の`z-index: 100`より確実に上に表示されるようにした。

- `scrollY: 2000`の状態で再現・修正確認済み（メニュー全8項目が画面全体を覆って正しく表示）。
- リンククリックによるページ遷移、メニューの閉じるアニメーションも問題ないことを確認済み。

## 配色の全面刷新（2026-07-29 追記⑬：深緑がAI感を出すため脱グリーン）

「深緑がAI感出る」という指摘を受け、明度・彩度の調整では解決しないと判断し、プライマリーカラーを緑から完全に離脱させた。ディープグリーン＋クリーム＋オレンジは「持続可能・地域密着」系ブランドでAIが提案しがちな定番配色そのものであり、色相自体を変える必要があった。

- Primary：`#1f8a4c`（緑）→ `#9a4e26`（テラコッタ/赤茶）
- Primary Dark：`#124025`（深緑）→ `#2b1d14`（エスプレッソブラウン）
- Accent：`#ce6708` → `#c98a1f`（黄金系、テラコッタと被らないよう調整）
- Header等にハードコードされていた旧・緑のrgba影も新配色に合わせて更新
- **イラストの中の緑（屋根・針葉樹・エプロン）はそのまま**。UIチェックアウト（ヘッダー・ボタン・見出し・暗い背景）だけを脱グリーンし、イラストとUIが同じ色相を無理に揃える必要はないという方針にした

ブラウザで確認済み、TypeScript/ESLintもクリア。

「ハンバーガーメニューを押してもページに移行しない」という不具合報告を受けて調査・修正した。

### 根本原因（コードのバグ、旧実装から存在していた）

`Header.module.css`の`.backdrop`（メニューを閉じるための透明な背景ボタン）が`position:absolute; inset:0`でオーバーレイ全体（`.menuPanel`のリンクが乗っている領域も含む）を覆っており、`.menuPanel`より後にDOMへ記述されていたため、z-index未指定のスタッキング順で**backdropが常にリンクの上に重なってクリックを奪っていた**。メニューを開いてリンクをクリックしたつもりが、実際は背後のbackdropがクリックを受け取ってメニューを閉じるだけになっていた。`.menuPanel { z-index: 2 }` / `.backdrop { z-index: 1 }` を明示して解決。

### 複数ページ化（1枚の`app/page.tsx`縦スクロール構成 → 実URLを持つ複数ページへ）

AGENTS.mdの定義どおり「HP」は実コードの複数ページ構成であるべきという指摘を受け、Next.js App Routerのルーティングで新規ページを追加した。

- `/floor`（Step02 現場を知る）
- `/career`（Step03 専門性を磨く）
- `/voices`（Step04 先輩の声）
- Header・Footerは`app/layout.tsx`に移動し全ページで永続化（ページ遷移で再マウントされない）。EntryCtaは各ページの`<main>`内に含め、全ページ末尾に表示。
- `data/site.ts`の`navLinks`/`steps`を実URL（`/floor`など）に変更し、`Header`・`Footer`・`Hero`のリンクをすべて`next/link`の`Link`に置き換え。
- ロゴのリンク先を`#top`（現在ページのトップへスクロールするだけで実質何も起きない）から`/`（実際にトップページへ戻る）に修正。
- `PageFixedUI`（左下固定CTA・右下回転Scrollバッジ）は、Headerが再マウントされないApp Router特有の事情に対応するため`usePathname()`を`useGSAP`の`dependencies`に渡し、ページ遷移のたびに古いScrollTriggerを破棄して`#hero`／`footer`を再取得するよう修正。`#hero`が存在しない下層ページ（/floor等）では、巨大な導入部がないため最初から表示する分岐を追加。

- CompanyIntroの統計カウントアップも、framer-motionの`animate`からGSAP（`gsap.to`のオブジェクトプロキシ＋`onUpdate`）へ置き換え。
- **`MaskImage`にカーテンワイプの初回リビール**（Neon: `image-curtain-reveal`）を追加。既存のスクラブ視差パン（`data-scroll-speed`相当）とは別レイヤーのタイムラインとして重ね、初回のみ`toggleActions: play none none none`で1回再生。
- **ヘッダーのスクロール時シェイプ変化**（Neon: `sticky-header-shrink`）を実装。`scrolled`state自体は既存実装済みだったが、対応するCSS（`.headerScrolled`）が未定義で見た目上何も起きていなかったバグを修正し、padding/ロゴ縮小/背景ブラーを追加。
- **参考サイト共通要素の再現**：左下固定「エントリーする」CTA＋右下の回転する「Scroll」円形テキストを、Hero内だけでなくサイト全体で永続的に表示する`PageFixedUI`コンポーネント（`src/components/PageFixedUI/`）として新規実装し、`layout.tsx`に追加。GSAP `ScrollTrigger.create`＋`toggleClass`でHero通過後に表示、フッター接近で非表示にする。

### 実装中に踏んだ落とし穴（今後の参考用）

1. **`useGSAP({ scope })`のセレクタスコープ**：`scope`を指定すると、文字列セレクタ（`"#hero"`, `"footer"`など）はscope要素の**内側のみ**で解決される（GSAPのcontext選択子）。scope外の要素をtriggerにしたい場合は、`document.querySelector`で先に要素を取得してから渡す必要がある（`PageFixedUI`のバグ）。コンソールの`Element not found: xxx`警告はこの兆候。
2. **`start`だけ指定して`end`を省略しない**：`end`のデフォルトは`"bottom top"`。`start`にも同じ値（例：`"bottom top"`）を指定すると、開始・終了が同一点になり有効レンジが実質ゼロになる（`toggleClass`が一瞬で戻る）。`end: "max"`はelement trigger＋独自startの組み合わせでは機能しなかったため、`end: 100000`のような大きな絶対px値で回避した。
3. スクリーンショットでマスク画像が中央の細い帯しか見えない・空白に見える場合、多くはバグではなく**カーテン/パンアニメーションが再生中の一瞬を捉えただけ**。1〜2秒待って再撮影し、`getBoundingClientRect()`やcomputed `transform`をJSで直接確認してから「バグ」と判断すること。

## 画像生成に関する既知の制約
