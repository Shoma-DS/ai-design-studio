## 既知のツール制約（コード側の不具合ではない）

- `resize_window`実行後も`window.innerWidth`が実際には変わらず（1440pxのまま）、この環境ではモバイル実機幅の自動化検証ができなかった。このスキルのドキュメントに記載されている既知の制約と一致する。
  - 対策として、`src/app/**/page.module.css`・`src/components/**/*.module.css`内の`@media`定義（1024px/768px/640px/480px）を直接コードレビューし、ブレークポイントごとのレイアウト崩れがないことを確認済み。実機・実ブラウザでの最終確認を推奨。
- ナビリンクの合成クリックが1回目で反応しないことがあった（2回目のクリックで正常に遷移）。これは自動化ツール環境固有の挙動で、実ブラウザでの手動操作では問題にならない可能性が高い。
- この環境では`document.hidden`が常に`true`のため、Aboutページの`<video>`が`readyState: 0`のまま復帰せず、ブラウザ自動化では再生確認ができない。
  - ファイル自体は正常。`fetch`はRangeリクエストに206を返し、`ffprobe`でh264 / 1280×720 / 19.9秒 / 597フレームを確認済み。
  - 内容の確認は、エンコード後の動画から各シーンのフレームを`ffmpeg -ss`で抜き出して目視した（全5シーン正常）。実ブラウザでの再生確認を推奨。
